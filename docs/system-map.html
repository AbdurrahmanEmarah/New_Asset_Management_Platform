Things you should be aware of

Decisions needed from you, later
  • Billing: manual invoices first, or a payment provider (Stripe, Paddle, a local gateway) from day one?
  • Email / SMS provider for invites and alerts, for example Azure Communication Services or SendGrid.
  • Data region: where client data lives (for example UAE North, West Europe). Some clients will require their own country.
  • Sub-domains: the domain name to buy, e.g. {client}.inventra.app.
Risks to watch
  • Azure cost: twelve services, each with its own database, cost more than one app. We'll group small services onto shared hosting in staging to keep the monthly bill low.
  • Offline sync in the field app is the hardest part to get right. It gets its own test suite.
  • Configurable fields must stay fast to search and filter at 50,000+ assets. They get indexes and a load test.
  • Not enforced yet: suspending a client is recorded, but blocking its users from signing in arrives with Access (patch 02). The same goes for usage counts, which stay at 0 until Access and Assets report them.
  • Usage limit: all five team sessions share your account's 5-hour usage limit. Running all five at once used it up in about 30 minutes, so they now restart in waves (Backend and Web first).
  • Your PC's disk space: Docker, PostgreSQL and the services need roughly 15–20 GB free to run locally.
Rules we follow
  • Never commit to main. Every change arrives as a patch after CI passes.
  • Every button either works or says why it can't. No silent failures.
  • The server checks every permission, not only the screens.
  • No AI costs unless you decide to add them.
Proposed additions (tell me if you disagree)
  • Gateway (YARP) in front of all services, so the apps have one address and one place to check tokens.
  • Search starts on PostgreSQL full-text search, so there's no extra search engine to pay for. We'll move to a dedicated search engine only if it gets too slow.
  • Sub-domain per client (gulf-fm.inventra…), so a link always opens the right company.
